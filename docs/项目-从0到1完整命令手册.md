## 阶段0 环境准备

### 0.1 母盘 + 完整克隆
- 母盘 RHEL 9.6，VMware Workstation 17.5，**完整克隆**（非链接克隆）出 5 台，按上表命名/配内存。
- 每台开机改主机名、静态 IP（见 0.2）。

### 0.2 网络配置（每台都做，替换 IP）
```bash
# 改主机名（例 master）
hostnamectl set-hostname k8s-master

# 配静态 IP（用 nmcli；把 IP 换成该节点的）
nmcli c modify eth0 ipv4.addresses 172.25.254.101/24
nmcli c modify eth0 ipv4.gateway 172.25.254.2
nmcli c modify eth0 ipv4.method manual
nmcli c modify eth0 ipv4.dns 223.5.5.5
nmcli c up eth0

# 验证
ip addr show eth0 | grep inet      # 应该 172.25.254.101/24
ping -c2 172.25.254.2              # 通网关
ping -c2 baidu.com                 # 通外网（本机若走代理需先 export）
```

### 0.3 关闭 SELinux / 防火墙 / swap + 内核参数（每台）
```bash
# 关 SELinux（临时+永久）
setenforce 0
sed -i 's/SELINUX=enforcing/SELINUX=disabled/' /etc/selinux/config

# 关防火墙
systemctl disable --now firewalld

# 关 swap（临时+永久）
swapoff -a
sed -i '/swap/s/^/#/' /etc/fstab

# 内核转发参数（K8s 跨节点通信必须）
modprobe br_netfilter
cat > /etc/sysctl.d/k8s.conf <<'EOF'
net.ipv4.ip_forward=1
net.bridge.bridge-nf-call-iptables=1
net.bridge.bridge-nf-call-ip6tables=1
EOF
sysctl --system

# 重启生效（可选，确认 SELinux/swap 关闭）
reboot
```

### 0.4 时间同步 + hosts（每台）
```bash
# 时间同步
dnf install -y chrony && systemctl enable --now chronyd && timedatectl set-ntp true

# hosts（所有节点互认）
cat >> /etc/hosts <<'EOF'
172.25.254.101 k8s-master
172.25.254.102 k8s-node1
172.25.254.103 k8s-node2
172.25.254.105 gitlab-server
172.25.254.106 gitlab-runner
EOF
```

### 1.1 装 Docker（每台）
```bash
dnf -y install dnf-utils
```

### 1.2 装 cri-dockerd（每台）
```bash
# 下载 cri-dockerd（kubeadm 用的 CRI 翻译官；若不连 docker hub，走代理）
export http_proxy=http://172.25.254.1:7897 https_proxy=http://172.25.254.1:7897
VERSION=v0.3.16
curl -L -o cri-dockerd.tgz https://github.com/Mirantis/cri-dockerd/releases/download/${VERSION}/cri-dockerd-${VERSION}.amd64.tgz
unset http_proxy https_proxy
tar xzf cri-dockerd.tgz -C /tmp
cp /tmp/cri-dockerd/cri-dockerd /usr/bin/
chmod +x /usr/bin/cri-dockerd

# 生成 systemd 单元（cri-dockerd 官方脚本）
curl -sSL https://raw.githubusercontent.com/Mirantis/cri-dockerd/master/packaging/systemd/cri-docker.service -o /etc/systemd/system/cri-docker.service
curl -sSL https://raw.githubusercontent.com/Mirantis/cri-dockerd/master/packaging/systemd/cri-docker.socket -o /etc/systemd/system/cri-docker.socket
systemctl daemon-reload
systemctl enable --now cri-docker
cri-docker --version
```

### 1.3 装 kubeadm/kubelet/kubectl（每台）
```bash
cat > /etc/yum.repos.d/kubernetes.repo <<'EOF'
[kubernetes]
name=Kubernetes
baseurl=https://mirrors.aliyun.com/kubernetes/yum/repos/kubernetes-el7-x86_64/
enabled=1
gpgcheck=0
EOF
dnf -y install kubelet kubeadm kubectl --disableexcludes=kubernetes
systemctl enable --now kubelet
kubeadm version
```

### 1.4 master 初始化（master 上）
```bash
kubeadm init \
  --apiserver-advertise-address=172.25.254.101 \
  --image-repository registry.aliyuncs.com/google_containers \
  --kubernetes-version v1.31.0 \
  --pod-network-cidr=10.244.0.0/16 \
  --cri-socket=unix:///var/run/cri-dockerd.sock

**【参数详解 · 阶段1.4 kubeadm init】**（这 5 个参数最关键，务必理解）
| 参数 | 作用 |
|---|---|
| `--apiserver-advertise-address` | master 的 API Server **对外监听 IP**(集群入口)。填 master IP `172.25.254.101`。👉 面试常问：**集群的"入口"是哪** |
| `--image-repository` | 拉 K8s 组件镜像的仓库。**国内用 `registry.aliyuncs.com/google_containers`**，避免直连 `k8s.gcr.io`(被墙)。👉 镜像源 |
| `--kubernetes-version` | K8s 版本，**必须和安装的 kubeadm/kubelet 一致**(都 v1.31.0) |
| `--pod-network-cidr` | **Pod 网段**。K8s 给每个 Pod 分 IP 的网段 `10.244.0.0/16`，**必须和网络插件(flannel)一致**，否则 Pod 之间不通。👉 高频追问 |
| `--cri-socket` | 告诉 kubeadm **用哪个容器运行时(CRI)**。用 cri-dockerd，所以指向 `unix:///var/run/cri-dockerd.sock`。👉 **为什么需要 cri-dockerd**：K8s 只说 CRI 语言、docker 只说 Docker 语言，cri-dockerd 当"翻译官" |

# 让 kubectl 可用
export KUBECONFIG=/etc/kubernetes/admin.conf
echo 'export KUBECONFIG=/etc/kubernetes/admin.conf' >> ~/.bashrc
kubectl get nodes
```

### 1.5 装 Flannel（master 上）
```bash
kubectl apply -f https://raw.githubusercontent.com/flannel-io/flannel/master/Documentation/kube-flannel.yml
kubectl get pods -n kube-flannel -o wide   # 等 Running
```
> 若 CrashLoopBackOff，见避坑直通版「坑1」/执行文档附录A-01（br_netfilter）。

### 1.6 node 加入（node1/node2；在 master 生成 join 命令）
```bash
# master 上生成（别手抄整条）
kubeadm token create --print-join-command

# node 上执行（把生成的那整条粘进来，再补 --cri-socket）
kubeadm join 172.25.254.101:6443 --token <TOKEN> \
  --discovery-token-ca-cert-hash sha256:<HASH> \
  --cri-socket unix:///var/run/cri-dockerd.sock

# master 上验证
kubectl get nodes        # 3 节点都 Ready
```

### 2.5 节点信任 Harbor（node1/node2/master）
```bash
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://docker.m.daocloud.io", "https://dockerproxy.net", "https://docker.1ms.run"],
  "insecure-registries": ["172.25.254.101"],
  "exec-opts": ["native.cgroupdriver=systemd"]
}
EOF
systemctl restart docker
```

**【参数详解 · 阶段2.5 daemon.json】**（这三个键务必理解）
| 键 | 作用 |
|---|---|
| `insecure-registries` | 让 docker **信任并明文连接 http 私有仓库**(Harbor 是 http)。不加 → docker 默认走 https(443)连 Harbor → 报 `connection refused`。👉 **高频面试** |
| `registry-mirrors` | 国内加速器。**`docker pull` 走 daemon 代理、`docker build` 拉基础镜像走这个加速器**(见基础命令教学手册§6.4)。👉 注意和代理的区别 |
| `exec-opts: native.cgroupdriver=systemd` | 让 docker 用 systemd 管 cgroup，**必须和 K8s 一致**(否则 kubelet 报错)。👉 高频 |

> 基础命令链接：`cat > <<'EOF'`(写文件)→基础命令手册§1.2；[systemctl restart](基础命令教学手册.md#cmd-systemctl)；docker 相关→§6。

## 阶段3 NFS 共享存储

### 3.1 master 服务端
```bash
dnf -y install nfs-utils rpcbind
mkdir -p /data/k8s/mysql /data/k8s/tomcat /data/k8s/nginx/html /data/k8s/nginx/nginx
cat > /etc/exports <<'EOF'
/data/k8s 172.25.254.0/24(rw,sync,no_root_squash,no_all_squash)
EOF
exportfs -rv
showmount -e localhost
systemctl enable --now nfs-server rpcbind
```

**【参数详解 · 阶段3.1 /etc/exports + exportfs】**
| 字段 | 作用 |
|---|---|
| `/data/k8s` | 共享出去的目录(服务器端) |
| `172.25.254.0/24` | **允许访问的网段**(只给这个网段共享) |
| `rw` | 读写；`sync` 同步写(数据落盘才返回) |
| `no_root_squash` | **允许 root 直写**(部署时容器常以 root 写 NFS，不开会被拦)；`no_all_squash` 同理。👉 面试点：**为什么 NFS 要 no_root_squash** |
| `exportfs -rv` | **重新导出**新目录/改配置。**新加共享目录必须跑**，否则客户端报 `No such file or directory`。👉 最经典坑 |
| `showmount -e localhost` | 看当前导出了哪些(验证) |

> 基础命令链接：`cat <<'EOF'`(写文件)→§1.2；[systemctl enable --now](基础命令教学手册.md#cmd-systemctl)；`exportfs/mount`→§5。
> **新加共享目录后必须 `exportfs -rv`**，否则节点挂载报 No such file or directory。

### 3.2 node 客户端（node1/node2）
```bash
dnf -y install nfs-utils
mkdir -p /data/nfs
mount -t nfs 172.25.254.101:/data/k8s /data/nfs
echo '172.25.254.101:/data/k8s /data/nfs nfs defaults 0 0' >> /etc/fstab
mount | grep nfs      # 已挂载
```

## 阶段4 MySQL 部署（master 上建 yaml）

### 4.1 mysql.yaml（PV/PVC/RC/Service 一整套）
```bash
cat > mysql.yaml <<'EOF'
apiVersion: v1
kind: PersistentVolume
metadata:
  name: mysql-pv
spec:
  capacity: {storage: 10Gi}
  accessModes: [ReadWriteMany]
  persistentVolumeReclaimPolicy: Retain
  nfs: {path: /data/k8s/mysql, server: 172.25.254.101}
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mysql-pvc
spec:
  accessModes: [ReadWriteMany]
  resources:
    requests: {storage: 10Gi}
---
apiVersion: v1
kind: ReplicationController
metadata:
  name: mysql
spec:
  replicas: 1
  selector: {app: mysql}
  template:
    metadata:
      labels: {app: mysql}
    spec:
      containers:
      - name: mysql
        image: 172.25.254.101/openlab/mysql:8.4.2
        ports: [{containerPort: 3306}]
        env:
        - {name: MYSQL_ROOT_PASSWORD, value: "123456"}
        volumeMounts:
        - {name: data, mountPath: /var/lib/mysql}
      volumes:
      - name: data
        persistentVolumeClaim: {claimName: mysql-pvc}
---
apiVersion: v1
kind: Service
metadata:
  name: mysql-svc
spec:
  type: NodePort
  selector: {app: mysql}
  ports:
  - {port: 3306, targetPort: 3306, nodePort: 30361}
EOF
kubectl apply -f mysql.yaml
kubectl get pv,pvc,pod,svc -o wide   # PV/PVC Bound + Pod Running + 30361
```

### 4.2 验证持久化
```bash
kubectl exec -it <mysql-pod> -- mysql -uroot -p123456 -e 'create database testdb;'
kubectl delete pod <mysql-pod>       # RC 自愈重建
kubectl exec -it <新mysql-pod> -- mysql -uroot -p123456 -e 'show databases;'  # testdb 还在=持久化成功
```

---

**【参数详解 · 阶段4.1 mysql.yaml 关键字段】**
| 字段 | 作用 |
|---|---|
| `nodePort: 30361` | Service 映射到宿主机**固定端口**，供集群外访问(mysql 用 30361)。👉 面试：K8s 怎么对外暴露服务 |
| `accessModes: [ReadWriteMany]`(RWX) | **多节点同时读写**共享存储(几个节点共用一块 NFS)。👉 面试：PV 为什么用 RWX |
| `persistentVolumeReclaimPolicy: Retain` | 删 PVC 时**保留** PV 数据(不自动删)。👉 面试：PV 回收策略 |
| `capacity: 10Gi` | PV 声明的容量 |
| `nfs: {path, server}` | PV 指向 NFS 共享目录(服务器IP + 路径) |

> 基础命令链接：`kubectl exec`(容器里跑命令)→§7.4；`kubectl delete pod`(验证自愈)→§7.4；`kubectl get pv,pvc`→§7.1；`kubectl apply -f`→§7.2。

**【参数详解 · 阶段5.2 kubectl cp】**
`kubectl cp demo.war <pod>:/usr/local/tomcat/webapps/` —— **跨容器隔离文件系统**拷文件。容器有独立文件系统(Linux namespace + OverlayFS)，宿主机 `cp` 进不去容器；`kubectl cp` 是**跨"隔离墙"的桥**。👉 面试：为什么用 kubectl cp 而不是 cp

> 基础命令链接：`kubectl cp`→§7.4；`kubectl get pod`→§7.1。

### 6.2 nginx 反代接入层（Deployment + ConfigMap）
```bash
cat > nginx-proxy-cm.yaml <<'EOF'
apiVersion: v1
kind: ConfigMap
metadata:
  name: nginxconf
data:
  default.conf: |
    server {
      listen 80;
      server_name www.openlab.com;
      location /nginx  { proxy_pass http://nginx-svc/; }
      location /tomcat { proxy_pass http://tomcat-svc:8080/; }
      location /       { root /usr/share/nginx/html; }
    }
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: nginx-index
data:
  index.html: |
    <h1>Hello Nginx, This is Nginx Web Page</h1>
EOF
kubectl apply -f nginx-proxy-cm.yaml

cat > nginx-proxy.yaml <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: open-nginx-proxy
spec:
  replicas: 1
  selector:
    matchLabels: {app: open-nginx-proxy}
  template:
    metadata:
      labels: {app: open-nginx-proxy}
    spec:
      containers:
      - name: nginx
        image: 172.25.254.101/openlab/nginx:1.27.1
        ports: [{containerPort: 80}]
        volumeMounts:
        - {name: conf, mountPath: /etc/nginx/conf.d}
        - {name: idx, mountPath: /usr/share/nginx/html}
      volumes:
      - name: conf
        configMap: {name: nginxconf}
      - name: idx
        configMap: {name: nginx-index}
EOF
kubectl apply -f nginx-proxy.yaml
kubectl expose deployment open-nginx-proxy --port=80

# 验证统一入口
kubectl get svc   # 见 open-nginx-proxy ClusterIP 80
curl <反代PodIP>/          # Hello Nginx...
curl <反代PodIP>/tomcat/demo/   # Hello, Demo App!
```
> 判断反代成功：404/403 是后端发的=转发成功；502 才是反代失败。

---

**【参数详解 · 阶段6.1 subPath】**
同一个 PVC(nginx) 通过 `subPath: html` / `subPath: nginx` 挂到容器**两个不同位置**：`/usr/share/nginx/html`(网页根) + `/etc/config`(配置目录)。PVC 里分 `html/`、`nginx/` 两个子目录，subPath 指定挂**哪个子路径**。👉 面试：同一个存储拆成两个挂载点怎么实现

> 基础命令链接：`kubectl apply`→§7.2；`kubectl expose`(把 Deployment 变 Service)→§7.5。

### 7.5 .gitlab-ci.yml（build→push→deploy）
```yaml

  HARBOR: 172.25.254.101
  PROJECT: openlab

  HARBOR_USER: admin

  stage: push
  script:
  - echo "${HARBOR_PASS}" | docker login ${HARBOR} -u ${HARBOR_USER} --password-stdin

  stage: deploy

  - kubectl patch rc tomcat --type='json' -p='[{"op":"replace","path":"/spec/template/spec/containers/0/image","value":"'${IMAGE}'"}]'
```

**【参数详解 · 阶段7.3 gitlab-runner register】**
| 参数 | 作用 |
|---|---|
| `--registration-token`(或 `-r`) | **注册**新 runner 用；**`--token`(或 `-t`)是验证**已有 runner 的——**用错会报 403**。👉 高频坑 |
| `--executor shell` | runner 直接在宿主跑命令(不需 docker socket 配置)；`docker` 则每个 job 独立容器但麻烦 |
| token 来源 | register 的 token 由 gitlab-runner **自己写入** config.toml，别从对话复制(会变省略号) |
| `KUBECONFIG` | kubectl 找集群配置的路径；deploy 阶段给 gitlab-runner 用户配好才能操作集群 |

```bash

  scrape_interval: 15s

- job_name: node-exporter
  static_configs:
  - targets: ['10.244.1.5:9100', '10.244.2.5:9100']

cat > prometheus.yaml <<'EOF'
apiVersion: v1
kind: ConfigMap
metadata: {name: prometheus-config, namespace: monitoring}
data:
  prometheus.yml: |
    global:
      scrape_interval: 15s
    scrape_configs:
    - job_name: node-exporter
      static_configs:
      - targets: ['10.244.1.5:9100', '10.244.2.5:9100']
---
apiVersion: v1
kind: ServiceAccount
metadata: {name: prometheus, namespace: monitoring}
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata: {name: prometheus}
rules:
- apiGroups: [""]
  resources: ["nodes","nodes/proxy","services","endpoints","pods","configmaps"]
  verbs: ["get","list","watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata: {name: prometheus}
roleRef: {apiGroup: rbac.authorization.k8s.io, kind: ClusterRole, name: prometheus}
subjects:
- {kind: ServiceAccount, name: prometheus, namespace: monitoring}
---
apiVersion: apps/v1
kind: Deployment
metadata: {name: prometheus, namespace: monitoring}
spec:
  replicas: 1
  selector: {matchLabels: {app: prometheus}}

    metadata: {labels: {app: prometheus}}

      serviceAccountName: prometheus
      containers:
      - name: prometheus

---
apiVersion: v1
kind: Service
metadata: {name: prometheus, namespace: monitoring}

  type: NodePort
  selector: {app: prometheus}
```
