# 一、文件与文本处理

<a id="cmd-cat"></a>
## 1.1 `cat` —— 查看/拼接/写文件
**是什么**：读文件内容到屏幕（concatenate 拼接）。
**常见3种用法**：
```bash
cat /etc/hosts           # ① 看文件内容
cat > file <<'EOF' ... EOF   # ② 写多行文件（见 heredoc）
cat >> /etc/hosts <<'EOF'    # ③ 追加内容到文件
```
- `>` 覆盖写；`>>` **追加**写（不覆盖）。本项目追加 hosts 用 `>>`。
- **本项目实际用法**：
  ```bash
  cat >> /etc/hosts <<'EOF'
  172.25.254.101 k8s-master
  ...
  EOF
  ```
  = 把 5 行节点映射**追加**到 /etc/hosts 末尾（节点相互之间认主机名）。

<a id="cmd-cat"></a>
## 1.2 `cat <<'EOF' ... EOF`（heredoc）—— 写多行文件
**是什么**：heredoc（here document），把括起来的一整段多行文本**一次写进文件**。
**语法**：`cat > 文件名 <<'EOF'` + 多行内容 + `EOF`(结束标记)。
- `<<'EOF'` 加**单引号** = 里面的 `$变量` **不展开**（原样写入）；不加引号会展开变量。
- **本项目用得多**：写 daemon.json、prometheus.yml、yaml、exports 等，都用 heredoc 一次成型，比一个个 echo 干净。
- **教学要点**：`EOF` 只是约定结束符，可换成任意词（END/DONE），但前后必须一致。**加单引号防变量展开**是安全习惯。

<a id="cmd-sed"></a>
## 1.3 `sed -i 's/旧/新/'` —— 编辑文件
**是什么**：流编辑器（stream editor），批量改文本。
**语法**：`sed -i 's/旧内容/新内容/' 文件`
- `s/旧/新/` = **替换**(substitute)，把每行第一个「旧」换成「新」。
- `-i` = **in-place**(就地改文件)，否则只打印不改文件。
- 结尾 `.` / `/g`：`s///g` = 整行所有都换；`s///` 只换每行第一个。
- 本项目 `sed -i` 二次元变换，展示：
  - 永久关 SELinux：`sed -i 's/SELINUX=enforcing/SELINUX=disabled/' /etc/selinux/config`
  - 工具链：`/etc/fstab` 里 `^#` 的意思是注释行。
- **本项目实际**：把 `SELINUX=enforcing` 这一行里的值改成 `disabled`（就地改配置）。

<a id="cmd-sed"></a>
## 1.4 `sed` 扩展：关 swap 那行的`/swap/s/^/#/`
```bash
sed -i '/swap/s/^/#/' /etc/fstab
```
拆解：`/swap/` = **只处理含 "swap" 的行**;`s/^/#/` = 把**行首 `^`** 替换成 `#`(注释掉)。= "把所有含 swap 的行注释掉"，从而禁用开机挂载 swap。

<a id="cmd-grep"></a>
## 1.5 `grep` —— 查找
**是什么**：global regular expression print，按关键词/正则筛选行。
```bash
grep proxy /etc/...        # 含 proxy 的行
grep -v swap 文件           # 排除含 swap 的行(-v 反向)
grep -n token 文件          # 显示行号(-n)
grep -iE "error|warn" 文件  # 忽略大小写 + 多关键词(-E 正则)
```
- **本项目**：`grep -n "token = " config.toml` 看 token 那行；`journalctl | grep -iE "error|forbidden"` 筛选日志。

<a id="cmd-head"></a>
## 1.6 `head` / `tail` / `-n` —— 看前后若干行
- `head -30 file`：看前 30 行；`tail -30 file`：看后 30 行（日志看尾部，最新报错）。
- `tail -f file`：**实时跟随**（持续输出）。排障时用。
- `| head` 管道：把前命令输出截取前 N 行。

<a id="cmd-echo"></a>
## 1.7 `echo` —— 打印/写一行
- `echo "xxx"`：打印。
- `echo 'export KUBECONFIG=...' >> ~/.bashrc`：追加一行到 .bashrc（持久化）。
- `echo value | command`：管道喂给命令（如 `echo "密码" | docker login ... --password-stdin` 有特殊说明）。
- `echo "" > file`：覆盖清空/写空。

# 二、系统与安全设置

<a id="cmd-setenforce"></a>
## 2.1 `setenforce 0` —— 临时关 SELinux
- **SELinux**：Linux 的强制访问控制（安全模块），默认 enforce 会限制很多进程/服务（K8s/容器尤其容易被拦）。
- `setenforce 0` = **临时设成 permissive(宽容)模式**，只记录不拦截。
- 要**永久**关：改配置文件 `/etc/selinux/config` 的 `SELINUX=disabled`（用 sed）。
- **为什么关**：K8s 数据面 + 容器 + NFS 常被 SELinux 拦截，本项目直接临时关掉避免大量排障。

<a id="cmd-systemctl"></a>
## 2.2 `systemctl` —— 管理 systemd 服务
**是什么**：systemd 是 Linux 的服务管理器；`systemctl` 是操作它的命令。**本项目高频**。
常用：
| 命令 | 作用 |
|---|---|
| `systemctl status 服务` | 看服务状态(active/inactive + 日志) |
| `systemctl start 服务` | 启动服务 |
| `systemctl stop 服务` | 停止服务 |
| `systemctl restart 服务` | **重启**服务(改配置后常用) |
| `systemctl enable 服务` | 开机自启 |
| `systemctl disable 服务` | 禁用开机自启 |
| `systemctl enable --now 服务` | 启动 + 设置开机自启(一步到位) |
| `systemctl disable --now 服务` | 停止 + 禁止开机自启(本项目关防火墙用) |
| `systemctl daemon-reload` | **重载 systemd 配置**(改了 service 文件后必做) |

**本项目**：
- `systemctl disable --now firewalld`：停防火墙 + 禁自启（K8s 需放开，直接关省事）。
- `systemctl enable --now docker`：docker 启动 + 自启。
- `systemctl daemon-reload && systemctl restart docker`：改了 daemon.json/代理后热加载。

<a id="cmd-swapoff"></a>
## 2.3 `swapoff -a` —— 临时关 swap
- **swap**：交换分区（用磁盘当内存溢出兜底）。**K8s 要求关闭**（kubelet 依赖，swap 会干扰资源调度/稳定性）。
- `swapoff -a`：临时关所有 swap(交换机)；要让开机也关：注释掉 /etc/fstab 里 swap 那行（sed）。
- **为什么 K8s 要关 swap**：K8s 按内存请求调度 Pod，若系统偷偷用 swap，kubelet 以为内存够、实际被打满 → 不稳定。面试可讲。

<a id="cmd-nmcli"></a>
## 2.4 `nmcli` —— 配网络（NetworkManager 命令行）
**是什么**：NetworkManager 的命令行工具，本项目配**静态 IP / 网关 / DNS** 用。
```bash
nmcli c modify eth0 ipv4.addresses 172.25.254.101/24   # 配 IP(带掩码)
nmcli c modify eth0 ipv4.gateway 172.25.254.2          # 配网关
nmcli c modify eth0 ipv4.method manual                 # 手动模式(不用 DHCP)
nmcli c modify eth0 ipv4.dns 223.5.5.5                 # 配 DNS
nmcli c up eth0                                        # 应用配置
```
- `c` = connection；`modify` = 改；`ipv4.addresses` 写法 `IP/掩码位数`(172.25.254.101/24 = 255.255.255.0)。
- **教学点**：`nmcli c modify` 是"改连接"、`nmcli c up` 是"激活"。改完必须 `up` 才生效。

<a id="cmd-chrony"></a>
## 2.5 `chrony` / `timedatectl` —— 时间同步
- `dnf install chrony && systemctl enable --now chronyd`：装+启动时间同步服务。
- `timedatectl set-ntp true`：开 NTP。
- **为什么重要**：K8s 证书/组件间通信对**时间**敏感，节点时间不一致会报错(kubelet 证书、watcher 异常)。面试可讲"集群要时间同步"。

<a id="cmd-reboot"></a>
## 2.6 `reboot` —— 重启
- 配完 SELinux(永久)/swap(永久) 后重启确认生效。
- `reboot` = 重启；`shutdown -r now` 同义。

# 三、内核与网络

<a id="cmd-modprobe"></a>
## 3.1 `modprobe` —— 加载内核模块
- **内核模块**：可插拔的驱动程序/功能（如 `br_netfilter` 是"网桥防火墙过滤"模块）。
- `modprobe br_netfilter`：加载这个模块（让网桥流量能被 iptables 处理）。
- **为什么 K8s 需要**：flannel 等网络插件靠 `br_netfilter` + 内核参数在**网桥**上做转发/过滤；缺模块 → flannel CrashLoopBackOff。**本项目最经典的坑**。
- 持久化：`echo br_netfilter > /etc/modules-load.d/k8s.conf` 让它开机自动加载。

<a id="cmd-sysctl"></a>
## 3.2 `sysctl` —— 查看/设置内核运行时参数
**是什么**：看/改内核运行参数（`/proc/sys` 对应值）。
```bash
sysctl -w net.ipv4.ip_forward=1            # 临时设置(-w write)
sysctl net.bridge.bridge-nf-call-iptables  # 查看
sysctl --system                            # 让 /etc/sysctl.d/*.conf 全部生效
```
**本项目 3 个关键参数**：
- `net.ipv4.ip_forward=1`：**允许 IP 转发**（跨节点/跨网络通信，K8s 容器网络依赖）。
- `net.bridge.bridge-nf-call-iptables=1`：**网桥流量交给 iptables**处理（flannel 转发 Pod 流量需要）。
- `net.bridge.bridge-nf-call-ip6tables=1`：IPv6 同理。
- **写入 /etc/sysctl.d/k8s.conf + `sysctl --system`**：持久化 + 立即生效。
- **面试高频**：怎么配这 3 个参数、为什么要、丢了会怎样（flannel 挂）。

<a id="cmd-ping"></a>
## 3.3 `ping` / `ip addr` / `ip route`
- `ping -c2 <IP>`：连通性测试(`-c2` = ping2次)。
- `ip addr show eth0 | grep inet`：看网卡 IP。
- `ip route`：看路由/网关。
- **本项目**：配完网络 ping 网关/外网验证通。

<a id="cmd-ss"></a>
## 3.4 `ss` / `netstat`
- `ss -lntp`：看**监听端口**(listen)。排障常用（如 80/6443 被谁占、端口起没起）。本项目用 **`ss -lntp | grep 80`** 查端口。

# 四、包管理与下载

<a id="cmd-dnf"></a>
## 4.1 `dnf` —— RHEL 包管理（yum 后代）
```bash
dnf -y install 包名            # 安装(-y 自动 yes)
dnf -y remove 包名             # 卸载
dnf config-manager --add-repo <repo url>   # 添加软件源(仓库)
dnf search 包名                # 搜
```
- **本项目**：`dnf config-manager --add-repo https://download.docker.com/.../docker-ce.repo` 加 docker 源；`dnf install docker-ce ...` 装 docker。
- `dnf --disableexcludes=kubernetes` 装 k8s 组件时排除被仓库规则排除。

<a id="cmd-curl"></a>
## 4.2 `curl` —— 下载/发请求
```bash
curl -L -o 文件名 "URL"      # 下载到文件(-L 跟随重定向,-o 输出文件名)
curl -s URL | head          # 拿内容(-s 静默)
curl -s http://IP            # 访问网页内容
curl -s -o /dev/null -w "%{http_code}" URL  # 只看 HTTP 状态码(200/502/403)
```
- **本项目**：`curl -L -o cri-dockerd.tgz <github地址>` 下载二进制；`curl -s http://172.25.254.101` 看 Harbor 通没通(200 vs 502)。
- 教学点：`-s`(静默)、`-L`(跳转)、`-o`(存文件)、`-w`(格式化输出)。

<a id="cmd-wget"></a>
## 4.3 `wget` —— 下载
- `wget <URL>`：下载到当前目录。
- **本项目**：`wget <harbor离线包> -O harbor.tgz`（`-O` 指定文件名）。

<a id="cmd-tar"></a>
## 4.4 `tar` —— 压缩/解压
```bash
tar xzf 文件.tgz -C 目录    # 解压到目录(x 解包,z gzip,f 文件,C 目录)
tar czf 包.tar.gz 文件夹     # 压缩(c 创建)
```
- **本项目**：`tar xzf harbor-offline...tgz -C /data/server/harbor/` 解 Harbor 离线包。

# 五、存储 NFS

<a id="cmd-exportfs"></a>
## 5.1 `exportfs` —— NFS 导出管理
**是什么**：管理 NFS 服务端的**导出清单**（哪些目录共享给谁）。
```bash
exportfs -rv         # r=重新导出,v=显示过程
showmount -e localhost   # 看当前导出了哪些目录
```
- **为什么必须 `exportfs -rv`**：NFS 靠 `/etc/exports` 这份"导出清单"提供目录；**新建了共享目录/改了 exports，必须重新导出，客户端才认识**。不导出 → 客户端挂载报 `No such file or directory`。**本项目 nginx 挂载失败就是这个**。
- 类比：新房间要**登记进访客名单**（exports），不然来宾敲门说"没这个房间"。

<a id="cmd-mount"></a>
## 5.2 `mount` / `/etc/fstab` —— 挂载
```bash
mount -t nfs 172.25.254.101:/data/k8s /data/nfs   # 手动挂载 NFS 到本地目录
echo '172.25.254.101:/data/k8s /data/nfs nfs defaults 0 0' >> /etc/fstab  # 开机自动挂载
mount | grep nfs     # 看是否已挂载
```
- `mount -t nfs 源 目录`：`-t` 文件系统类型(nfs)、`源(服务器IP:共享路径)`、`本地挂载点`。
- `/etc/fstab` 4 段格式：`设备/源 挂载点 文件系统 选项 是否dump 是否fsck`。写进去开机自动挂。
- **教学点**：`mount` 是把"远端目录"映射到"本地目录"，之后本地读写就是读远端。

<a id="cmd-NFS"></a>
<a id="cmd-NFS"></a>
## 5.3 NFS 相关包/服务
- `dnf install nfs-utils rpcbind`：装服务端/客户端工具。
- `systemctl enable --now nfs-server rpcbind`：启动 NFS 服务。
- 服务端配置在 `/etc/exports`（`/data/k8s 172.25.254.0/24(rw,sync,no_root_squash,no_all_squash)`）。

# 六、Docker

## 6.1 镜像相关
```bash
docker pull nginx:1.27.1                # 拉镜像(从仓库)
docker images                           # 看本地镜像
docker tag <镜像> 172.25.254.101/openlab/nginx:1.27.1   # 打 tag(贴"仓库地址"名片)
docker push 172.25.254.101/openlab/nginx:1.27.1        # 推镜像到 Harbor
docker login 172.25.254.101 -u admin   # 登录私有仓库(push 必须)
docker rmi <镜像>                        # 删镜像
```
- **`tag`原来是干啥**：镜像名决定它属于哪个仓库；tag 给同一镜像贴"完整地址(仓库/项目/镜像:版本)"的名片，push 按新名字推。image ID 不变，只改名。
- **`login` 为什么必须**：push 私有项目要凭证；pull 私有项目也要登录（公开的免登录）。
- 本项目：`docker pull` 走 **daemon 代理**；`docker build` 拉基础镜像走 **registry-mirrors**（两码事，见避坑直通版坑7.11）。

## 6.2 容器/运行
```bash
docker run -d --name gitlab --restart unless-stopped -p 80:80 -p 443:443 -p 2222:22 -v gitlab-etc:/etc/gitlab -v gitlab-log:/var/log/gitlab -v gitlab-opt:/var/opt/gitlab --shm-size 256m --hostname gitlab-server gitlab/gitlab-ce:latest
docker ps -a                    # 看所有容器(-a 含已停止)
docker exec -it gitlab bash      # 进容器执行命令(-it 交互)
docker logs gitlab               # 看容器日志
docker rm -f gitlab              # 强删容器(-f)
docker volume create gitlab-etc  # 建数据卷
```
- `-d` 后台运行；`--restart unless-stopped` **开机自启**；`-p 宿主机:容器` 端口映射；`-v 卷:容器内路径` 持久化数据；`--shm-size` 共享内存(容器常见坑)。
- **本项目**：GitLab 用 `-p 2222:22` 避开源宿主 sshd 的 22；`docker exec gitlab cat /etc/gitlab/initial_root_password` 取初始密码。

<a id="cmd-docker"></a>
## 6.3 `docker compose` —— 编排一组容器
```bash
docker compose up -d      # 拉起一组容器(yml 定义)
docker compose ps         # 看这一组状态
docker compose down       # 停这一组
```
- `docker compose`(新版，空格) = 旧 `docker-compose`(横杠)。
- **本项目**：Harbor 约 10 个容器，用 compose 一键管理；Harbor 不健康时 `docker compose up -d` 幂等恢复。

<a id="cmd-daemonjson"></a>
<a id="cmd-daemonjson"></a>
## 6.4 daemon.json / 代理
- `/etc/docker/daemon.json`：docker 守护进程配置（registry-mirrors、insecure-registries、exec-opts）。
- 改完要 `systemctl daemon-reload && systemctl restart docker`。
- `insecure-registries`: 让 docker **信 http 私有仓库**；`registry-mirrors`: 国内加速器(`docker build` 拉基础镜像用)。

# 七、kubectl

## 7.1 查询
```bash
kubectl get nodes            # 看节点
kubectl get pods -o wide     # 看 Pod(-o wide 展开列:IP/所在节点)
kubectl get all              # 所有常见资源
kubectl get pv,pvc           # 逗号分隔看多类
kubectl get -n monitoring    # 限定命名空间; -A 全部
```
- `-o wide`：多显示几列(Pod 的 IP/节点)。`-o yaml/json/name`：结构化输出。

## 7.2 创建/应用
```bash
kubectl apply -f xxx.yaml     # 创建或更新(幂等),ConfigMap/Deployment 用这个
kubectl create -f xxx.yaml    # 只创建(重复报已存在)
kubectl delete -f xxx.yaml / kubectl delete pod x
kubectl create namespace monitoring
```
- `apply` vs `create`：apply 幂等(可反复跑)，create 只建一次。
- 本项目 yaml 多用 `apply`。

## 7.3 排障三件套
```bash
kubectl describe pod <pod>    # 看对象详情+**Events(事件)**——排障第一步
kubectl logs <pod>            # 看容器日志(应用输出/报错)
kubectl logs <pod> --tail=50  # 只看最后50行
```
- 通用排障四步：①get 看状态 → ②describe 看事件 → ③logs 看日志 → ④定位根因修复。
- 本项目 flannel/nginx 排障全靠 describe/logs。

## 7.4 操作内部
```bash
kubectl exec -it <pod> -- bash    # 进容器的 shell(-it 交互)
kubectl exec -it <mysql-pod> -- mysql -uroot -p   # 容器里跑命令
kubectl cp demo.war <pod>:/usr/local/tomcat/webapps/   # 拷文件进容器
kubectl delete pod <pod>          # 删 Pod(RC/Deployment 会自动重建→自愈)
```
- **为什么要 kubectl cp**：容器有**独立隔离文件系统**，宿主机 cp 进不去，kubectl cp 是"跨隔离墙的桥"。

<a id="cmd-Service"></a>
<a id="cmd-Service"></a>
## 7.5 Service / 发布
```bash
kubectl expose deployment open-nginx-proxy --port=80     # 把 Deployment 暴露成 Service
kubectl get svc                                          # 看 Service(ClusterIP/NodePort)
kubectl patch rc tomcat --type='json' -p='[...]'         # 就地改(CI/CD 更新镜像用)
kubectl rollout restart deployment/prometheus            # 滚动重启
kubectl set serviceaccount deployment/prometheus prometheus -n monitoring  # 换服务账号
kubectl auth can-i list pods -n monitoring --as=system:serviceaccount:monitoring:prometheus  # 测某身份权限(yes/no)
```
- `-n` 命名空间；Service 的 `nodePort` 是对外暴露的固定端口。

# 八、GitLab / Runner

<a id="cmd-gitlab-runner"></a>
## 8.1 `gitlab-runner register` —— 注册 runner
```bash
gitlab-runner register --non-interactive \
  --url http://172.25.254.105 \
  --registration-token <TOKEN> \
  --executor shell \
  --description "k8s-runner"
```
- `--registration-token`(或 `-r`)：**注册**新 runner 用；**`--token`(或 `-t`)是验证**已有 runner 的——**别搞混**(注册用 -r)。
- `--executor shell`：runner 直接在宿主跑命令(省掉 docker socket 配置)；也可 `docker`(每个 job 独立容器，但麻烦)。
- **教学点**：register 把配好写入 `/etc/gitlab-runner/config.toml`，token 由 gitlab-runner 自己生成（**别从对话复制**，会变省略号）。

<a id="cmd-usermod"></a>
## 8.2 `usermod -aG docker gitlab-runner`
- `usermod -aG <组> <用户>`：把用户**追加**进某组(-aG = append to group)。
- **本项目**：`usermod -aG docker gitlab-runner` 让 gitlab-runner 用户能用 docker(否则 shell executor 下 `docker build` 权限不足)。改完 `systemctl restart gitlab-runner`。
- `id gitlab-runner`：看用户在哪些组(验证加没加成功)。

## 8.3 查看日志/服务
```bash
journalctl -u gitlab-runner -n 60 --no-pager   # 看 gitlab-runner 服务日志(-u 服务名,-n 条数)
systemctl status gitlab-runner                 # 看服务状态
gitlab-runner list                             # 看已注册的 runner
gitlab-runner verify                           # 验证 runner 连接
```
- `journalctl -u <服务>`：看某 systemd 服务的日志(排障 runner 无 403/job 不跑)。
- `--no-pager`：不分页直接输出。
